# VehicleRefiner — 차량 5종을 원본 크롭으로 다시 가르는 2단 분류기 (설계, 2026-11-28)

사용자가 Gemini 와 따로 나눈 '모델 직접 설계' 대화의 Stage 3 을 이 저장소의 데이터·코드에 맞춰 다시 짠 설계다. 목적은
**자동 라벨링 정확도 + 연구·공부**(DetectView 실시간 배포는 아니다). **아직 코드는 없다** — 단계마다 사용자 확인을 받고 만든다.
이 문서의 수치는 2026-11-28 DB 사본(승인 383장)으로 쟀다. 측정 방법은 각 줄에 적었다.

## 1. 풀려는 문제와 기대치

- 검출기는 `car / pickup / truck / bus / responder` 를 클래스마다 따로 시그모이드(BCE)로 내고, 분류 헤드는 DWConv 두 층이다
  (Ultralytics 8.4.212 `nn/modules/head.py` 의 `Detect.cv3`). 차종을 가르는 단서(적재함이 캡과 나뉘었나·열렸나, 경광등·도색)는
  1280 으로 줄인 그림에서 몇 px 다.
- 11-18 newtest8(운영 m, 1280)의 클래스 틀림 22건 중 21건이 차량끼리, 18건이 pickup 이 낀 짝이었다(docs/experiments.md).
- **기대치를 먼저 적어 둔다.** 이 분류기는 클래스만 고친다 — 놓침·헛 박스는 그대로다. m1280 의 첫 분할 test(44장, 정답 279개)는
  놓침 50 · 헛 박스 23 · 클래스 틀림 14 이고(11-28, one2many+NMS 헤드), newtest8 은 놓침 8 · 헛 박스 23 · 틀림 22 다. 틀림은 정답의
  5% 안팎이라, 다 고쳐도 자동 라벨링을 고치는 일의 일부만 준다. 공부 거리로는 좋다: 미세 분류·확률 보정·그룹 교차 검증·
  쌍 비교 검정을 한 실험에서 다 해 본다.

## 2. 데이터

### 2.1 크롭 풀

승인 이미지의 차량 박스 가운데 **가릴 영역이 반 넘게 덮은 박스는 뺀다**(`masks.drops` — 학습 세트·데이터 점검과 같은 판정).
**11-27 첫 분할(사본)의 test 카메라 26대는 통째로 뺀다** — 그 test 로 2단 전체를 마지막에 재기 때문이다(5절). 그 분할 뒤에 들어온
88장은 test 카메라에서 온 것이 0장이라 풀에 넣는다. 분할 소속은 WSL `~/datasets/n1280/images/<분할>/` 의 파일 이름(`<원래 이름>__<해시>`)
으로 되짚었다(295장 전부 맞음).

| 클래스 | 풀의 크롭 | 그중 긴 변 48px 이상 | 카메라 수 | (뺀 test 카메라의 크롭) |
|---|---|---|---|---|
| car | 726 | 640 | 142 | 119 |
| pickup | 77 | 74 | 33 | 13 |
| truck | 117 | 115 | 46 | 20 |
| bus | 50 | 48 | 28 | 6 |
| responder | 33 | 32 | 10 | 8 |
| 합 | 1,003 | 909 | | 166 |

- **responder 는 카메라 10대뿐이고 한 대가 14개를 갖는다**(풀 전체 41개 기준, 12대). 어느 방법이든 responder 수치는 크게 흔들린다 —
  따로 보고만 하고 고를 때 기준으로 쓰지 않는다.
- pickup 은 33대에 고르게 퍼져 있다. 이 실험의 주 대상이다.

해상도: 직접 모은 것 2560×1440 127장 · 1920×1080 67장 · 사진 4장, AI Hub 1920×1080 185장. 긴 변(원본 px, 가려진 박스 뺌):

| 클래스 · 출처 | 수 | 긴 변 p10 / p50 / p90 | 48px 미만 | 192px 이상 |
|---|---|---|---|---|
| car · 직접 | 463 | 49 / 109 / 258 | 40 | 95 |
| car · AI Hub | 382 | 42 / 118 / 391 | 58 | 121 |
| pickup · 직접 | 70 | 73 / 131 / 268 | 2 | 13 |
| truck · 직접 | 108 | 101 / 199 / 454 | 0 | 55 |
| bus · 직접 | 36 | 126 / 269 / 505 | 1 | 24 |
| responder · 직접 | 40 | 118 / 258 / 488 | 1 | 28 |

- 2560 원본을 1280 으로 줄이면 pickup 중앙값이 131 → 65px 이 된다. 원본에서 자르면 픽셀이 두 배다(2.3절 R2 가 이것이 실제로
  도움이 되는지 잰다 — 운영 m(640 학습)을 newtest8 에서 1280 → 1920 으로 돌려도 클래스 틀림은 24 → 21 로 거의 안 줄었다,
  docs/experiments.md 11-12 표. 배운 크기 밖의 입력이라 깨끗한 비교는 아니다).
- **48px 문턱(gate):** 그보다 작은 박스는 분류기에 넣지 않고 검출기 클래스를 그대로 둔다. 거의 다 먼 car 다(pickup·truck·bus·
  responder 는 합쳐 4개).

### 2.3 크롭 만들기 규칙

- 좌표는 라벨과 같은 **EXIF 회전을 적용한 화면 기준**이다. 크기는 `yolo_io.display_size`, 그림은 `plain_image_open` +
  `ImageOps.exif_transpose`(루트 CLAUDE.md 'EXIF 회전 이미지'·src/autolabel/CLAUDE.md '`yolo_io.image_size`').
- 박스를 사방으로 박스 크기의 15% 넓혀(문맥 — R3 에서 0·15·40% 비교) 그림 안으로 자른 **원본 해상도 그대로**를 저장한다.
  모델 입력 크기로 줄이는 것은 학습 때 한다(가로세로비를 지키는 레터박스, 빈칸은 YOLO 와 같은 회색 114).
- '1280 시야' 비교(R2)는 따로 저장하지 않는다. 원본 크롭을 그림 긴 변이 1280 이 되는 배율(2560 → 0.5, 1920 → 0.667)로 줄였다가
  입력 크기로 키운다(검출기가 본 픽셀만 남긴다).
- 목록 `manifest.csv`: 크롭 경로, image_id, camera, 출처(직접·AI Hub), 11-27 분할(train·val·test·new), fold, 클래스, 원본 박스
  x·y·w·h, 그림 W·H, domain, 촬영 시각.
- **둘 곳은 저장소 밖** `C:\datasets\vehicle_crops_<날짜>\`(이 PC 의 다른 실험 사본과 같은 자리). **AI Hub 크롭(카메라 `ah-*`)은
  이 PC 밖으로 보내지 않는다**(Runpod·git·Roboflow 금지 — 루트 CLAUDE.md '먼저 물을 것'). **Claude 는 크롭을 열지 않는다** —
  눈으로 볼 것은 대조 시트를 만들어 경로만 알린다.

## 3. 구조

```
원본 그림 ──(검출기 박스, 긴 변 ≥ 48px, 차량 클래스)──▶ 크롭(문맥 15%) ──레터박스──▶ x : B×3×224×224
                                                                                   │
  기하 g = [log(w/h), w/W, h/H, cy/H] : B×4                                          ▼
        │                                                       백본 (아래 표) ─▶ B×C×7×7 ─GAP─▶ B×C
        └─▶ MLP 4→32→32 (SiLU) ─▶ B×32 ──────────────────────────────┐                        │
                                                                     └──── concat ◀───────────┘
                                                                            │  B×(C+32)
                                                                     Dropout 0.2 → Linear (C+32 → 5)
                                                                            │  logits z : B×5
                                                                     softmax(z / T)  ← T 는 학습 뒤 맞춤(4.3)
```

### 3.1 백본 후보

FLOPs 는 `torch.utils.flop_counter.FlopCounterMode`(곱셈·덧셈을 따로 셈)로 11-28 에 쟀다. 같은 셈법으로 yolo26m 검출기 전체는
1280 입력에서 303 GFLOPs 다.

| id | 백본 | 사전학습 | 파라미터 | GFLOPs (224) | 나오는 특징 | 가중치 |
|---|---|---|---|---|---|---|
| B1 | yolo26m 층 0–10(SPPF·C2PSA 포함) | COCO `weights/yolo26m.pt` | 10.35M | 4.81 | 512×7×7 | 있음 |
| B2 | 같은 구조 | 운영 m `models/best_y26m_8cls.pt`(옛 CCTV 3,725장) | 10.35M | 4.81 | 512×7×7 | 있음 |
| B2b | 같은 구조 | 옛 데이터 10클래스(11-24, responder·cone 을 배운 것) | 10.35M | 4.81 | 512×7×7 | 있음(사본 폴더) |
| B3 | ResNet-18 | ImageNet-1k | 11.7M | 3.63 | 512×7×7 | torch 캐시에 있음 |
| B4 | ConvNeXt-Tiny | ImageNet-1k | 28.6M | 8.91 | 768×7×7 | **내려받기 필요(약 110MB) — 사용자 허락** |

- 160·288 입력이면 B1 은 2.45·7.95 GFLOPs 다(R5).
- **B1·B2 는 내려받을 것이 없고, 검출기와 같은 층이라 공부 거리가 된다**: '일반 사진(ImageNet) 대 검출(COCO) 대 우리 CCTV 로
  미세조정한 특징' 을 같은 분류 머리로 견준다. B2 는 옛 데이터의 라벨 기준으로 배운 특징이다. 또 직접 모은 test 의 라벨이
  운영 m 의 예측을 사람이 고친 것이라 B2 에 유리할 수 있다(docs/experiments.md 11-27 절의 '한계').
- 한 장에 차량이 10대면 B1 은 48 GFLOPs, 검출기(1280)의 16% 다. 자동 라벨링에는 문제가 안 된다.

### 3.2 머리와 기하 가지

- **GAP → (기하 32차원 concat) → Dropout → Linear 5.** 5-way softmax 라 한 박스에 클래스 하나가 강제된다(검출기의 독립 BCE 와 다르다).
- **기하 가지(R4):** 크롭에서 사라지는 크기·비율·화면 속 위치. CCTV 는 위치(cy)가 거리와 엮여 크기를 해석하는 데 도움이 될 수
  있지만, **카메라마다 차선 자리가 정해져 있어 '이 자리면 버스' 같은 지름길을 배울 수도 있다** — 그래서 카메라째 나눈 교차 검증(4.2)
  에서만 판정한다.
- 6번째 클래스 '차량 아님'(검출기 헛 박스를 거르는 일)은 이번 범위 밖이다. 1단계가 통과하면 다음 실험으로 둔다.

## 4. 학습과 평가

### 4.1 학습

| 항목 | 값 | 이유 |
|---|---|---|
| 입력 | 224, 레터박스(회색 114) | 가로세로비가 단서다(bus·truck 은 길다) — 늘리지 않는다 |
| 증강 | 좌우 뒤집기 0.5 · 밝기·대비·채도 ±0.3 · 색조 ±0.02 · 흑백 0.1(야간 적외선) · 흐림 0.2 · JPEG 품질 30–90 0.3 | CCTV 화질 흉내 |
| 박스 흔들기 | 중심 ±8% · 크기 0.9–1.15배 | 실제로는 검출기 박스로 자른다 — GT 박스에만 맞추지 않게 |
| 쓰지 않는 증강 | 상하 뒤집기·큰 회전 | CCTV 에서 안 나오는 모양 |
| 손실 | 교차 엔트로피 + label smoothing 0.05 | |
| 불균형 | 클래스 빈도의 제곱근 역수로 뽑기(car 640 대 responder 32 → 약 4.5배) | R7 에서 손실 가중과 비교 |
| 최적화 | AdamW, 백본 2e-4 · 머리 2e-3, weight decay 0.05, cosine, warmup 2, 40 epoch, batch 64, AMP | |
| seed | 고르는 비교는 셋 | 11-18 실험에서 seed 만 바꿔도 0.04 가까이 흔들렸다 |

크롭 900개 남짓이라 한 fold 가 몇 분일 것이다(추정 — 아직 안 쟀다). GPU 두 장이면 비교 둘을 나란히 돌린다(DDP 는 쓰지 않는다).

### 4.2 1단계 — 크롭으로 재는 교차 검증 (고르기는 여기서만)

- **카메라째 5-fold**(`StratifiedGroupKFold` — 그룹 = 분할이 통째로 옮기는 묶음: 같은 카메라, dHash 로 이어진 카메라, AI Hub 같은
  자리 쌍 `runs/aihub_split_1127/ah_groups.json`). 크롭이 박스 하나하나라 표본이 검출 test(44장)보다 훨씬 많다 — 차이를 읽을 수
  있는 곳은 여기다.
- **기준선 A0 — 운영 m(8클래스).** 이 이미지들을 본 적이 없다. 통째 그림을 1280 · one2many+NMS 로 돌려 GT 차량 박스와
  IoU ≥ 0.45 로 짝지은 예측의 클래스를 '검출기의 답' 으로 본다. responder 를 모르니 car·pickup·truck·bus 넷으로만 견준다.
  짝이 없는 GT(놓침)는 따로 센다.
- **기준선 A0b — 같은 fold 로 학습한 검출기(선택).** A0 은 '다른 데이터로 배운 1단 대 우리 데이터로 배운 2단' 이라 구조 차이와
  데이터 차이가 섞인다. 깨끗이 가르려면 fold 마다 yolo26m 1280 b5 를 학습한다(한 번 23.4분, 다섯 번 — GPU 두 장으로 약 1시간,
  추정). 사용자 결정.
- **지표:** 정확도, macro-F1, 클래스별 재현율, 5×5 혼동표, pickup 이 낀 틀림 수, ECE(보정 오차 — T 맞춘 전·후), 크기 구간별 정확도.
  fold 밖 예측을 모아(OOF) 한 번에 센다.
- **쌍 비교:** 같은 크롭에 두 방법이 낸 답을 짝지어 McNemar 정확 검정(한쪽만 맞힌 수끼리 견줌). 신뢰구간은 카메라 그룹째 부트스트랩.
- **미리 정해 두는 통과 기준** (결과를 보고 바꾸지 않는다):
  1. pickup 이 낀 틀림(pickup↔car, pickup↔truck)이 기준선보다 30% 이상 줄고 McNemar p < 0.05
  2. car 재현율이 1%p 넘게 내려가지 않음
  3. T 를 맞춘 뒤 ECE ≤ 0.05

### 4.3 확률 보정

T 하나(temperature scaling)를 fold 밖 예측의 음의 로그우도로 맞춘다. 맞춘 확률은 6절의 '바꿀 때의 문턱 τ' 와 검수 화면의
'확실'(`predict.confident_at` 0.90) 판단에 쓸 수 있다.

### 4.4 2단계 — 2단 전체를 고정 test 로

1단계를 통과하면 풀 전체로 학습한 분류기를 m1280 best.pt(11-27, 같은 분할의 train 으로 배움) 뒤에 붙여 첫 분할 test 44장을 잰다.
`wsl/eval_test.py` 의 `IgnoreValidator` 처럼 `update_metrics` 앞에서 예측의 클래스만 바꾸는 검증기를 만들면 mAP·`at_conf`·
가릴 영역 처리를 그대로 쓴다. 견줄 것: 검출기만 / 검출기 + 분류기 / GT 박스에 분류기(상한). **test 의 차량은 car 119 · truck 20 ·
pickup 13 · bus 6 · responder 8 이라** pickup 한 개가 8%p 다 — 맞는 방향인지 보는 확인이지 고르는 잣대가 아니다.

## 5. 비교 실험 (하나에 가설 하나)

| id | 바꾸는 것 | 가설 |
|---|---|---|
| R1 | 백본 B1 · B2 · B2b · B3 · (B4) | CCTV 로 미세조정한 특징(B2)이 일반 특징보다 낫다 |
| R2 | 원본 크롭 대 '1280 시야' 크롭 | 원본 픽셀이 차종 판정을 돕는다 — 아니면 병목은 데이터·경계 사례다 |
| R3 | 문맥 0 · 15 · 40% | 주변(차선·옆 차와의 크기 비교)이 도움이 된다 |
| R4 | 기하 가지 켬·끔 | 크기·위치가 돕는다 — 카메라째 검증에서도 남아야 진짜다 |
| R5 | 입력 160 · 224 · 288 | 크롭 중앙값(130px 안팎)보다 큰 입력은 이득이 작다 |
| R6 | 백본 얼림(선형 탐침) 대 전부 학습 | 특징만으로 얼마나 갈리는가(R1 의 해석을 돕는다) |
| R7 | 제곱근 역수 뽑기 대 손실 가중 | 드문 클래스 처리 방식 |
| R8 | 옛 데이터 크롭 더하기 | **사용자 결정 — 옛 데이터 되살리기는 11-12 부터 보류 중이다.** 하게 되면 car·pickup·truck·bus 만 쓴다(옛 사본의 responder 는 사람이 다 본 것이 아니라 car·truck 로 남은 것이 섞여 있을 수 있다). 라벨 기준(11-02 van→car, pickup 1a/1b)이 지금과 같은지 먼저 볼 것 |
| R9 | 카메라째 대 무작위 5-fold | 무작위로 나누면 같은 카메라가 양쪽에 들어가 점수가 부푼다 — 얼마나인지 재 둔다(공부용) |

순서: 크롭 만들기 → A0 → R1·R6 → R2 → R3·R5 → R4 → R7 → R9 → (A0b) → 2단계.

## 6. 자동 라벨링에 붙이기 (1·2단계를 통과한 뒤에만)

- **자리:** `AutoLabeler.run` 에서 검출이 `found` 로 모인 직후, `Box` 로 옮기기 전 — `src/autolabel/predictor.py` 의
  `boxes: list[Box] = []` 바로 앞(11-28 기준 233행). 통째·타일 두 길이 모두 여기를 지난다. 차량끼리 겹친 박스 정리
  (`tiling.cross_class_keep`)는 그 앞에서 이미 끝나 있다.
- **검출기가 본 배열에서 자른다** — 좌표가 그 배열 기준이다. 타일 길은 `img` 가 있고, 통째 길은 같은 함수
  (`ultralytics.utils.patches.imread`)로 한 번 읽는다.
- 프로젝트 클래스가 차량 다섯 가운데 하나이고 긴 변이 48px 이상인 박스만 넣는다. softmax 최댓값이 τ(1단계에서 정밀도 쪽으로 맞춤)
  이상이고 클래스가 다르면 바꾼다. 박스 conf 는 검출기 값 그대로 둔다(박스가 있는가의 확신).
- 끄고 켜는 설정은 `predict.refiner`(가중치·gate·τ, 기본 끔). 바꾼 이미지는 `model_version` 끝에 `+ref<해시 8자>`(타일의
  `+tiles` 와 같은 식).
- **예측 비교(P)·`tools/label_qa.py` 에는 처음에 걸지 않는다** — 둘은 모델이 낸 그대로 견준다(지금 규칙). 걸게 되면 둘 다 함께.
- GPU 는 자동 라벨링 작업의 잠금 안에서 쓴다(작업마다 한 번 올린다). 시험은 `tests/test_predictor.py` 처럼 가짜 분류기로.
